# Freshness wording audit

Line numbers refer to the revised source; the compact-label follow-up below supersedes the original per-row dating policy. This inventory includes matching source lines (including accessibility text, metadata, and template strings); identifiers and comments alone are excluded. Generated airport.js is audited alongside its template. No _ref directory was present.

Home uses the existing 30 minute STALE_MIN rule, missing timestamps, and FAA stale_feeds. Airport builds and runtime use that same age rule; failed-feed flags propagate through build_web. TV retains its existing 20 minute stale-banner rule. Weather observations and forecasts retain their existing observation-age and forecast-expiry checks. A missing reading is unavailable, never clear.

Current FAA claims use past tense or explicit as-of context when stale. Neutral program labels describe the listing, not a flight's punctuality. “Last FAA check <date/time> (<age>): no FAA programs listed …” limits the stale home verdict to the FAA listing evidence. Navigation “Live board”, stream controls “Watch live”, static product metadata, historical “clear”, user-entered flight scripts and “Do this now” instructions describe a destination, service, past reading, or user action, not FAA freshness. Alert reports have their own expires_utc signal, independent of state.json; they are dated reports and expired alerts are removed.
